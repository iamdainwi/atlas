## 2. Product: NovaPay

NovaPay is NovaTech's flagship B2B payment infrastructure product. It allows businesses to integrate payment collection, disbursals, and reconciliation through a single API.

### 2.1 Key Features

- **Payment Collection:** Accepts UPI, cards (Visa/Mastercard/Amex), net banking, and wallets.
- **Payouts:** Real-time payouts to bank accounts via IMPS/NEFT/RTGS.
- **Smart Reconciliation:** Auto-reconciles transactions within 2 hours of settlement.
- **Webhooks:** Event-driven notifications for payment status changes.
- **Dashboard:** Real-time analytics with 90-day data retention on free plans, unlimited on paid.
- **Multi-currency:** Supports INR, USD, SGD, AED, GBP, EUR. No MYR support as of v3.2.1.

## 4. API Reference

### 4.1 Authentication

All API requests must include a Bearer token in the Authorization header.

```http
GET /v1/payments HTTP/1.1
Host: api.novapay.io
Authorization: Bearer <your_api_key>
Content-Type: application/json
```

API keys are generated from the **Dashboard > Settings > API Keys** section. Each key has:
- **Type:** `test` or `live`
- **Permissions:** `read`, `write`, or `admin`
- **Expiry:** Optional, up to 365 days

> **Warning:** Never expose your live API key in client-side code. Use server-side calls only.

### 4.2 Create Payment Order

**Endpoint:** `POST /v1/orders`

**Request Body:**

```json
{
  "amount": 50000,
  "currency": "INR",
  "receipt": "order_rcpt_001",
  "customer": {
    "name": "Rahul Sharma",
    "email": "rahul@example.com",
    "phone": "9876543210"
  },
  "notes": {
    "product_id": "prod_xyz"
  }
}
```

**Response:**

```json
{
  "id": "order_PQr7x9AbCd",
  "status": "created",
  "amount": 50000,
  "currency": "INR",
  "created_at": "2025-03-14T10:22:00Z"
}
```

**Amount is always in the smallest currency unit.** For INR, `50000` = ₹500.00.

### 4.3 Webhook Payload Structure

```json
{
  "event": "payment.captured",
  "payload": {
    "payment_id": "pay_Abc123XyZ",
    "order_id": "order_PQr7x9AbCd",
    "amount": 50000,
    "currency": "INR",
    "status": "captured",
    "method": "upi",
    "captured_at": "2025-03-14T10:23:45Z"
  }
}
```

Supported webhook events:
- `payment.created`
- `payment.captured`
- `payment.failed`
- `payment.refunded`
- `payout.processed`
- `payout.failed`

### 4.4 Error Codes

| Code  | HTTP Status | Meaning                                     |
|-------|-------------|---------------------------------------------|
| 1001  | 400         | Invalid amount (must be > 0)                |
| 1002  | 400         | Unsupported currency                        |
| 1003  | 401         | Invalid or expired API key                  |
| 1004  | 403         | Insufficient API key permissions            |
| 1005  | 429         | Rate limit exceeded                         |
| 1006  | 422         | Customer phone number format invalid        |
| 2001  | 500         | Internal server error — contact support     |
| 2002  | 503         | Service temporarily unavailable             |

## 7. Deployment Checklist

Before pushing any release to production, the following must be completed:

- [ ] All unit tests passing (`npm run test`)
- [ ] Integration tests passing on staging environment
- [ ] Load test conducted with minimum **10,000 concurrent requests**
- [ ] Security scan completed via Snyk (zero critical vulnerabilities)
- [ ] API changelog updated in `docs/changelog.md`
- [ ] Webhook retry logic tested for all 6 event types
- [ ] Database migrations reviewed and rolled back tested
- [ ] Approval from **at least 2 senior engineers** and **Head of Product**
- [ ] Status page incident response plan updated
- [ ] Rollback procedure documented and tested

## 8. SLA & Uptime Policy

### 8.1 Uptime Commitments

| Plan       | Monthly Uptime SLA | Max Downtime/Month |
|------------|--------------------|--------------------|
| Starter    | 99.5%              | ~3.6 hours         |
| Growth     | 99.9%              | ~43.8 minutes      |
| Enterprise | 99.99%             | ~4.4 minutes       |

### 8.2 Compensation Policy

If NovaTech fails to meet the SLA in a given month:

| Downtime Exceeded By | Credit Given             |
|----------------------|--------------------------|
| Up to 1 hour         | 10% of monthly fee       |
| 1–4 hours            | 25% of monthly fee       |
| 4–12 hours           | 50% of monthly fee       |
| 12+ hours            | 100% of monthly fee      |

**Compensation is credited to the NovaTech account balance only.** No cash refunds are issued. Credits expire in 90 days if unused.

> **Exclusions:** Downtime caused by third-party payment networks (e.g., UPI infrastructure outages), customer-side issues, or force majeure events are excluded from SLA calculation.
